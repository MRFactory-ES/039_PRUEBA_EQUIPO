Testing Pull requests

Cómo cambiar tu página del tablón y pedir que se publique

Cada uno tiene su propia página en el tablón del equipo. La idea es practicar cómo se trabaja entre varios sin pisarnos: cambias tu página en tu ordenador, la pruebas, la subes y pides permiso. Coke lo revisa y, si está bien, sale publicado.

El camino de un cambio

Las tres reglas

Solo tu páginaCambia únicamente paginas/tu-nombre.html. Nada más.
Siempre en tu ramaNunca trabajes en main. GitHub no te dejará subir ahí.
Siempre pidiendo permisoTodo entra por un Pull Request que aprueba Coke.
La web del tablón: mrfactory-es.github.io/039_PRUEBA_EQUIPO
El proyecto en GitHub: github.com/MRFactory-ES/039_PRUEBA_EQUIPO

Palabras que vas a ver

  • Rama: tu copia de trabajo. Lo que hagas ahí no toca lo de nadie.
  • Commit: guardar un cambio con una frase que diga qué has hecho.
  • Pull Request: «he cambiado esto, ¿lo metes?». Es la petición de permiso.
  • main: la versión buena, la que sale en la web. Solo entra lo aprobado.

Antes de empezar · solo la primera vez

Sirve igual para Mac y para PC. Todo es gratis.

  1. Hazte una cuenta en GitHub en github.com, si no la tienes. Pásale a Coke tu nombre de usuario.
  2. Acepta la invitación a MRFactory-ES que te llegará por correo. Sin esto no podrás bajar el proyecto.
  3. Instala GitHub Desktop desde desktop.github.com. Ábrelo y entra con tu cuenta de GitHub.
  4. Instala Visual Studio Code desde code.visualstudio.com. Es el programa con el que vas a cambiar tu página.
  5. Baja el proyecto a tu ordenador. En GitHub Desktop, menú File → Clone Repository…
  6. En la pestaña GitHub.com elige MRFactory-ES/039_PRUEBA_EQUIPO y pulsa Clone. Abajo te dice en qué carpeta lo guarda. Déjala como está.

¿Ha ido bien?

Arriba en GitHub Desktop pone Current Repository: 039_PRUEBA_EQUIPO y Current Branch: main. Ya lo tienes en tu ordenador.

Hacer un cambio y verlo en tu ordenador

Esto se repite cada vez que quieras cambiar algo.

Bajar lo último (el «pull»)

  1. Abre GitHub Desktop. Arriba, en Current Branch, tiene que poner main. Si pone otra cosa, púlsalo y elige main.
  2. Pulsa Fetch origin. Si el botón cambia a Pull origin, púlsalo otra vez. Así tienes lo último que han aprobado los demás.

Crear tu rama

  1. Menú Branch → New Branch…
  2. Ponle de nombre tu nombre y lo que vas a cambiar, sin espacios ni tildes. Por ejemplo vero-titulo. Pulsa Create Branch. Ahora arriba, en Current Branch, pone el nombre de tu rama.

Cambiar tu página

  1. Menú Repository → Open in Visual Studio Code.
  2. A la izquierda, abre la carpeta paginas y haz clic en tu fichero (por ejemplo vero.html).
  3. Cambia lo que quieras entre las dos marcas ✏️: el título, los textos, la lista. Más arriba hay otra marca ✏️ para cambiar tu color.
  4. Guarda: Cmd + S en Mac, Ctrl + S en PC.

Verlo en tu ordenador

  1. En GitHub Desktop: menú Repository → Show in Finder (en PC, Show in Explorer).
  2. Haz doble clic en index.html. Se abre el tablón en el navegador. Pulsa tu tarjeta y verás tu página con el cambio.
  3. ¿Quieres cambiar algo más? Cambia, guarda y recarga el navegador: Cmd + R en Mac, F5 en PC. Esto solo lo ves tú. La web del equipo no cambia hasta que lo subas y Coke lo apruebe (página siguiente).

Subir tu cambio y pedir permiso

  1. Vuelve a GitHub Desktop. A la izquierda sale tu fichero; a la derecha, en rojo lo que quitas y en verde lo que pones.
  2. Abajo a la izquierda, en Summary, escribe en pocas palabras qué has cambiado. Por ejemplo: Cambio mi título.
  3. Pulsa el botón azul Commit to vero-titulo (sale con el nombre de tu rama).
  4. Arriba pulsa Publish branch. Tu rama sube a GitHub.
  5. Pulsa Preview Pull Request y luego Create Pull Request. Se abre GitHub en el navegador.
  6. En GitHub, pulsa otra vez el botón verde Create pull request. Ya está. A Coke le llega el aviso.

Si Coke te pide un cambio

  • Te lo dice en un comentario del Pull Request, en GitHub.
  • Sigue en tu misma rama: cambia, guarda, escribe el Summary y Commit to …
  • Arriba pulsa Push origin. El Pull Request se actualiza solo; no hay que abrir otro.

Cuando Coke lo aprueba

  • En 1 o 2 minutos tu cambio sale en la web del tablón.
  • En GitHub Desktop, vuelve a main (Current Branch → main) y pulsa Fetch origin y Pull origin.
  • Para el siguiente cambio, empieza otra vez en el paso 1 con una rama nueva.

Si algo sale raro

  • «No puedo subir» o «protected branch»: estás en main. Crea tu rama (paso 3) y, si te pregunta, elige llevarte tus cambios a la rama nueva.
  • «This branch has conflicts»: otra persona ha cambiado lo mismo que tú. Avisa a Coke y lo resolvéis juntos.
  • No ves tu cambio en el navegador: ¿has guardado (Cmd/Ctrl + S) y recargado?
